# 0.1.1 — 2026-05-24

## Added

- **10 tools:** `ref_geo_lookup`, `ref_geo_search`, `ref_timezone_lookup`, `ref_timezone_convert`, `ref_element_lookup`, `ref_element_search`, `ref_constant_lookup`, `ref_unit_convert`, `ref_http_status`, `ref_mime_type`
- **3 resources:** `ref://countries/{alpha2}`, `ref://elements/{number}`, `ref://timezones/{iana_id}`
- **geo-service** — country lookup and search via `countries-list`; ISO 3166-1 α-2/3, languages, currencies, calling codes, timezones per country
- **timezone-service** — IANA timezone lookups and offset conversion via `Intl` + `@vvo/tzdb` metadata
- **elements-service** — 118-element periodic table (PubChem/IUPAC 2024); atomic mass, electron configuration, electronegativity, density, phase, discovery data
- **constants-service** — ~360 CODATA 2022 physical constants with fuzzy alias matching
- **units-service** — numeric unit conversion via `convert-units`; length, mass, volume, temperature, speed, pressure, energy, power, frequency, digital storage, angle
- **http-status-service** — IANA HTTP status code registry (~65 codes) with keyword search
- **mime-service** — MIME type lookups via `mime-db` (~1,000 types with extension mappings)
- **97 tests** across all 10 tools (Vitest)
- No API keys, no runtime network calls — all datasets bundled at startup; works offline

## Fixed

- `ref_geo_search` — result set was missing `callingCode` and `languages` fields in sparse matches
- `ref_timezone_convert` — DST offset was applied twice when source timezone was also DST-active
- `ref_element_search` — `by: symbol` lookups were case-sensitive; now normalized before match
- `ref_constant_lookup` — alias fuzzy match returned wrong entry when two aliases shared a prefix
- `ref_unit_convert` — temperature conversions from Fahrenheit produced incorrect values for negative inputs
- `ref://countries/{alpha2}` resource — returned 404 for lowercase codes; now uppercases before lookup
