# 0.1.6 — 2026-05-28

## Changed

- **`@cyanheads/mcp-ts-core` ^0.9.9 → ^0.9.13** — adopts four upstream releases:
  - `MCP_HTTP_MAX_BODY_BYTES` — configurable inbound request-body cap; oversized requests rejected with `413` before SDK parsing (default 1 MiB; `0` to disable). ([#157](https://github.com/cyanheads/mcp-ts-core/issues/157))
  - HTTP session-init gate — stateful HTTP mode rejects non-`initialize` requests without an `Mcp-Session-Id` header with `400`. ([#154](https://github.com/cyanheads/mcp-ts-core/issues/154))
  - `httpErrorHandler` — expected client errors (401, 403, 400, 404) now log at `warning` instead of going through the full error pipeline, reducing noise. ([#158](https://github.com/cyanheads/mcp-ts-core/issues/158))
  - `GET /mcp` now surfaces `package.json` `keywords` on the status JSON response. ([#165](https://github.com/cyanheads/mcp-ts-core/issues/165))
- **`landing.requireAuth: false`** added to `createApp()` — opts the server out of the new auth-gated landing default; this server is a public catalog deployment. ([#156](https://github.com/cyanheads/mcp-ts-core/issues/156))
- **`ref_element_search`** `no_filters` error code: `InvalidParams` → `ValidationError` (client-observable).
- **`ref_geo_search`** `no_filters` error code: `InvalidParams` → `ValidationError` (client-observable).
- **`ref_unit_convert`** `incompatible_units` and `below_absolute_zero` error codes: `InvalidParams` → `ValidationError` (client-observable).

## Security

- Inherits upstream `MCP_HTTP_MAX_BODY_BYTES` 413 body cap from `@cyanheads/mcp-ts-core` ^0.9.13.
